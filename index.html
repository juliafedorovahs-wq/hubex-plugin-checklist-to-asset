Настройка правил переноса данных в карточку объекта

Правило определяет одно поле-источник (из чек-листа или из самой заявки) и одно поле объекта, куда оно копируется. Стадия, при переходе на которую срабатывает перенос, задаётся отдельно — в настройке вебхука, не здесь. Сам перенос выполняет отдельный сервис — этот экран только настраивает правила текущего тенанта.

Правило Источник Исходное поле Целевое поле Условие перезаписи Статус
Область действия: правила настраиваются отдельно в каждом тенанте — плагин открывается внутри админки тенанта и видит только его чек-листы, заявки и атрибуты.

Проверка типов при сохранении: тип поля-источника и поля объекта должен совпадать — иначе сохранить правило нельзя. Для полей типа «список» (Select) одного типа недостаточно: у чек-листовых/заявочных и объектных Select-полей независимые справочники вариантов (listOfValues), поэтому дополнительно сверяются сами варианты ответа — если наборы не совпадают, сохранение тоже заблокировано, пока варианты не приведены к одному виду.

Стадия не хранится в правиле: когда именно срабатывает перенос, определяет вебхук (событие + стадии, на которых он вызывается) — это настраивается отдельно от правила. Правило описывает только пару полей и условие перезаписи.
Какие вызовы API стоят за этим экраном (тенант «Производство», проверено живым вызовом)
Источник = Чек-лист, шаг «чек-лист» → GET /WORK/CheckLists — 5 чек-листов в тенанте
Источник = Чек-лист, шаг «поле» → GET /WORK/CheckLists/{id}/items — берём только пункты, где attribute != null (это касается и Switch-пунктов — у них тоже есть привязанный атрибут)
Источник = Заявка, шаг «поле» → GET /COMMON/Attributes?isRelevantForTask=true — 14 полей
Поле объекта → GET /COMMON/Attributes?isRelevantForAsset=true — 13 полей
Тип поля — из attributeType.code (чек-лист) или type.code (COMMON/Attributes, другое имя поля в ответе) — используется для проверки совместимости
Варианты списка (Select) → GET /Attributes/{attributeID}/listOfValues для обоих полей — в этом макете подставлены иллюстративные варианты, живой вызов не успел (токен тенанта истёк за 30 мин)
Триггер (не в этом экране) — вебхук HubEx: POST /MSG/Webhooks с events + taskStages — стадия(и), на которых он срабатывает, настраивается там
Сама запись значения в объект (не этот экран, делает отдельный сервис, вызванный вебхуком) → POST /ES/AssetAttributes/v2
